# 合格の街 〜塾長シミュレーター〜

中学受験塾の経営シミュレーションゲーム。Rust で書かれており、**Windows アプリ**と **WebAssembly（ブラウザ）** の両方で動きます。
UI は既存の UI フレームワークを使わず、`winit`（ウィンドウ・入力）と `wgpu`（GPU 描画）の上に自作しています。

- 企画・設計：[`docs/proposal/`](docs/proposal/README.md)

## 遊び方

最初は 1 教室の塾長として、毎週「次の週へ」を押して経営を進めます。資金が貯まったら別のエリアに教室を増やしていきます。

| タブ | できること |
|------|-----------|
| 教室 | 保護者の口コミ（4 軸評価）、気になる生徒、教室長の能力・年俸・業務委任、講師の採用と退職 |
| コース | 在籍数の推移、宿題の量（学力とストレスのトレードオフ）、コースの開講と料金（粗利つき） |
| 集客 | エリアの生徒シェア、競合塾の動き、ブランド力・認知度、8 種類の集客施策 |
| 経理 | 教室の損益計算書（前週比つき）、会社全体の成績（教室別・本部費用）、企業価値 |
| 本部 | 経営（教室一覧・首都圏攻略マップで開校・塾の買収）／財務・上場（塾長の個人資産・株式上場・銀行融資・物件）／人材・教材（スター講師の引き抜き・自社教材・教材の外販）／その他（年間カレンダー・入試結果・保存・ヘルプ） |

- **入試**：毎年 2 月 1 日に入試があり、全教室の 6 年生の合否が会社の「ブランド力」として翌年の集客を左右します。
- **首都圏攻略**：首都圏の実在の 16 の街（吉祥寺・成城学園前・浦和・渋谷・横浜・豊洲など）を、緯度経度どおりの地図（東京湾・多摩川・荒川・江戸川・主な鉄道）の上で攻略します。吉祥寺で創業し、東京西部 5 街から始めて、教室 3 つで埼玉、5 つで神奈川、7 つで湾岸・千葉、上場すると都心に出店できます（市場規模・家賃・競合・市場の伸びがそれぞれ違う）。地域で在籍数 1 位・シェア 35%・在籍 30 人を超えるとその街を「制覇」です。教室が増えたら教室長への業務委任が鍵です。
- **街と校舎の絵**：首都圏の地図・16 の街の風景・16 の校舎を、フラットなイラスト調で描いています。街ごとに時間帯と季節、景色の型が違い、校舎には「あおぞら進学塾 〇〇校」の看板が掛かります（[画像の一覧と描き方](docs/images/README.md)）。
- **自社教材**：市販教材から自社教材に切り替えると、網羅性・難度・わかりやすさ・演習量・入試対応の 5 軸を改訂で鍛えられます。入試対応は毎年古くなります。
- **競合塾**：大手 4 社（大手難関型・面倒見型・格安オンライン型・個別指導型）と、地域の個人塾・中小塾が 4 週ごとに動き、値下げ・広告・出店・撤退・講師の引き抜きを仕掛けてきます。
- **銀行融資**：利益・所有物件・ブランド・信頼で融資枠と金利が決まります。5 年／10 年の元金均等返済で、繰り上げ返済もできます。
- **物件**：教室の物件を買うと家賃がなくなり、維持費（年 1.5%）だけになります。地価は年 2% 上がり、融資の担保にもなります。
- **塾の買収**：後継者不足や経営難で売りに出た個人塾・中小塾を買えます。自塾のないエリアなら新しい教室に、あるエリアなら既存の教室に統合されます。
- **教材の外販**：自社教材を他の塾に月額で提供できます。契約は教材の質・ブランド・価格で増え、改訂を怠ると解約されます。地域の競合塾にも売ると契約は増えますが、相手も強くなります。
- **株式上場**：教室 4 つ・年間純利益 8,000 万円・2 年連続黒字・信頼などの条件を満たすと、1 年の準備を経て上場できます。株式を売り出して資金を調達し、以後は株価で会社と塾長の個人資産が評価されます。
- **スター講師の引き抜き**：競合の看板講師に 3 段階の条件で声をかけられます。成功すると集客力が上がり生徒もついてきますが、相手に恨まれて仕返しの引き抜きが増えます。
- **秘書**：ヘッダーの「秘書」を押すと、競合の値下げや出店、講師不足、退塾の原因、資金繰りなどを、数字つきで具体的に報告してくれます。重要なことは週を進めたときに自分から知らせてくれます。
- **チュートリアル**：はじめて遊ぶときは秘書が画面を順に案内します（本部 → その他 → ヘルプからもう一度見られます）。
- **倒産**：資金がマイナスのまま 26 週たつか、マイナス 3,000 万円を下回ると倒産（ゲームオーバー）です。
- **倫理イベント**：宿題の増量要望、志望校を下げさせるか、合格実績の上積みなど、短期の数字と長期の信頼を天秤にかける判断が起こります。

## 構成

```
crates/
  juku-sim/       ゲームロジック（描画・OS 非依存、決定論的、テストつき）
  juku-render/    wgpu の 2D バッチレンダラ（SDF 図形・グリフアトラス）
  juku-ui/        自作の即時モード UI ツールキット（レイアウト・ウィジェット・グラフ）
  juku-platform/  Windows / Web の差分（ウィンドウ・入力・GPU 初期化・保存）
  juku-app/       画面とゲーム進行
bins/
  juku-desktop/   Windows 版のエントリ（フォントを exe に埋め込み）
  juku-web/       Web 版のエントリ（cdylib）
web/              index.html と Cloudflare 用 _headers
assets/images/    地図・街・校舎の絵（tools/gen_images.py で描く）
assets/fonts/     Noto Sans JP（JIS 第 1・第 2 水準にサブセット化、SIL OFL）
tools/            Web ビルド・フォントのサブセット化
```

## 開発

```sh
# テスト（主にシミュレーション）
cargo test --workspace

# バランス確認：6 つの自動プレイ戦略 × 5 年 × 8 シード（詳細は docs/proposal/03 の 11 章）
cargo run -p juku-sim --example balance --release -- 5 8

# ネイティブで起動（Windows では exe ができる）
cargo run -p juku-desktop --release
```

### Windows 版

```sh
cargo build -p juku-desktop --release --target x86_64-pc-windows-msvc
# => target/x86_64-pc-windows-msvc/release/yyshop.exe（単体で動く）
```

セーブデータは `%APPDATA%\YYshop\saves\` に保存されます。

### Web 版

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.130 --locked   # Cargo.lock と同じ版
./tools/build-web.sh                                        # => dist/
python3 -m http.server -d dist 8080                         # http://localhost:8080
```

`wasm-opt`（binaryen）が入っていれば自動でサイズを最適化します。
描画は WebGL2 を使います（iOS の Safari などで WebGPU だと画面が真っ暗になることがあったため。URL に `?gpu=webgpu` をつけると WebGPU を試せます）。動作中のエラーは画面の下に表示されます。セーブデータは localStorage に保存されます。

### Cloudflare へのデプロイ

`dist/` は静的ファイルだけなので、Cloudflare Workers の静的アセット配信にそのまま置けます。
`wrangler.toml` の `[build]` で、デプロイの直前に `tools/cloudflare-build.sh` が `dist/` を作ります。
Rust や `wasm-bindgen` が入っていない環境（Cloudflare のビルド環境など）では、自動でインストールしてからビルドします。

```sh
npx wrangler deploy            # ビルドしてからデプロイ
npx wrangler deploy --dry-run  # ビルドだけ確かめる
```

**Cloudflare の Git 連携（Workers Builds）** で配信する場合は、ダッシュボードの設定を次のようにします。

| 項目 | 値 |
|------|----|
| ビルドコマンド | （空欄） |
| デプロイコマンド | `npx wrangler deploy` |

ビルドは `wrangler deploy` が `[build]` から実行するので、ビルドコマンドは不要です。初回は Rust のインストールとコンパイルで数分かかります。

#### デプロイとキャッシュ

`wrangler deploy` は新しいファイル一式をまとめて差し替えるため、通常は Cloudflare 側でキャッシュを削除（Purge）する必要はありません。ブラウザ側のキャッシュは次の設計で、デプロイ後に自動で新しい版に切り替わります。

| ファイル | キャッシュ | 新しい版への切り替わり |
|----------|-----------|------------------------|
| `index.html`、`manifest.webmanifest` | `no-cache`（毎回サーバーに確認） | 次に開いたとき |
| `pkg/*.wasm`、`pkg/*.js` | 1 年・immutable | ファイル名に内容のハッシュが入る |
| `assets/`（フォント・アイコン） | 1 年・immutable | URL に `?v=<内容のハッシュ>` が付く（`tools/build-web.sh` が計算） |

それでも古い画面が残る場合（独自のキャッシュルールを設定した、拡張機能やプロキシが残している等）は、ゲーム内の **本部タブ → ヘルプ →「キャッシュを削除して再読み込み」** を使ってください。Cache Storage と Service Worker を削除し、フォントを HTTP キャッシュを使わずに取り直してから再読み込みします。セーブデータ（localStorage）は消えません。

Cloudflare のゾーンにキャッシュルールを追加している場合は、ダッシュボードの「Caching → Configuration → Purge Everything」で削除してください。

なお、セーブデータの形式（`SAVE_VERSION`）を変えたデプロイの後は、古いセーブは読み込まれず「はじめから」になります。

GitHub Actions（`.github/workflows/ci.yml`）はテスト・バランス確認・Windows 版と Web 版のビルドだけを行い、デプロイはしません（Cloudflare の Git 連携に任せます）。
